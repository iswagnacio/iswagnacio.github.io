Goal

Part 2: Homography and Image Rectification

Understanding Homography

A homography is a projective transformation that maps points from one plane to another. In the context of images, it describes how a planar surface appears from different viewpoints. By computing the homography matrix H, we can transform images taken from different perspectives to align them or correct distortions.

1. Mathematical Foundation

Homography Equation

For a point (x, y) in one image and its corresponding point (x', y') in another image, the homography relationship is:

⎡ x' ⎤ ⎡ h₁₁ h₁₂ h₁₃ ⎤ ⎡ x ⎤
⎢ y' ⎥ = λ · ⎢ h₂₁ h₂₂ h₂₃ ⎥ · ⎢ y ⎥
⎣ 1 ⎦ ⎣ h₃₁ h₃₂ h₃₃ ⎦ ⎣ 1 ⎦

Where λ is a scaling factor and H is the 3×3 homography matrix with 8 degrees of freedom (h₃₃ = 1).

Solving for Homography

Given n ≥ 4 point correspondences, we can solve for H using a system of linear equations. Each point correspondence provides 2 equations, forming an overdetermined system that can be solved using least squares (SVD).

Point Correspondences

In this image pair, we compute the following H:

⎡ 1.04e+00 -1.29e-02 -4.46e+02 ⎤
H = ⎢ 3.45e-02 9.98e-01 -3.20e+01 ⎥
⎣ 4.29e-05 -1.41e-05 9.70e-01 ⎦

By applying this homography, we can "tilt" other images around a central image.

Rectification Process

  1. Define correspondences: Select 4+ points on the tilted plane and their desired positions in the rectified view
  2. Compute homography: Solve the linear system to find the transformation matrix H
  3. Warp image: Apply H to transform the original image to the rectified view
  4. Verify: Check that parallel lines remain parallel and right angles are preserved

Part 2: Creating Image Mosaics

Panorama Creation

Image mosaicing combines multiple overlapping images into a single wide-angle panorama. The process involves computing homographies between image pairs, warping them to a common coordinate system, and blending them seamlessly.

1. Mosaic Pipeline

Step-by-Step Process

  1. Image Capture: Take overlapping photos with 30-50% overlap while rotating around the camera center
  2. Correspondence Selection: Manually select matching points in overlapping regions
  3. Homography Computation: Calculate transformation matrices for each image pair
  4. Image Warping: Transform all images to a common reference frame
  5. Blending: Combine warped images using alpha blending or multiresolution techniques

Limitations of Simple Alpha Blending

  • Visible Seams: Abrupt transitions create noticeable boundaries between images
  • Wedge Artifacts: Linear blending weights create characteristic wedge-shaped ghosting
  • Frequency Mismatch: High-frequency details don't align perfectly, creating double edges
  • Exposure Differences: Variations in brightness between images become apparent at seams

Part 3: Optimized Blending with Laplacian Pyramids

Multiresolution Blending

To eliminate the wedge-like artifacts and visible seams from basic blending, we implement Laplacian pyramid blending. This technique, inspired by the classic Burt and Adelson paper, blends images separately at different frequency bands, allowing smooth transitions for low-frequency content while preserving sharp high-frequency details.

1. Laplacian Pyramid Theory

Why Multiresolution Blending?

The key insight is that our visual system is sensitive to different spatial frequencies at different scales. By decomposing images into frequency bands and blending each band with an appropriate transition width, we can:

  • Low frequencies: Blend gradually over wide regions to avoid brightness discontinuities
  • High frequencies: Blend sharply to preserve edge details and avoid ghosting
  • Result: Seamless transitions without visible artifacts

Mathematical Framework

Gaussian Pyramid Construction:

  • G₀ = Original Image
  • Gᵢ₊₁ = Blur(Gᵢ) - Progressive smoothing without downsampling
  • Each level represents increasingly low-pass filtered versions

Laplacian Pyramid Construction:

  • Lᵢ = Gᵢ - Gᵢ₊₁ - Bandpass filter at scale i
  • L₍ₙ₋₁₎ = Gₙ - Lowest frequency residual
  • Each level captures details at a specific frequency band

Blending Process:

  • Create Gaussian pyramid for the blending mask
  • For each level i: Blend_Lᵢ = L_Aᵢ × Mask_Gᵢ + L_Bᵢ × (1 - Mask_Gᵢ)
  • Reconstruct: Result = Σ Blend_Lᵢ

2. Implementation Details

Pipeline for Panorama Blending

  1. Warp Images: Apply homography transformations to align all images
  2. Create Masks: Generate binary masks for each warped image indicating valid pixel regions
  3. Distance Transform: Convert masks to distance fields for smooth blending weights
  4. Build Pyramids: Construct Laplacian pyramids (typically 5-7 levels) for each image and Gaussian pyramids for masks
  5. Blend Levels: At each pyramid level, blend images using corresponding mask weights
  6. Reconstruct: Collapse the blended pyramid to create the final panorama

Key Parameters

  • Pyramid Levels: 5-7 levels provide good frequency decomposition
  • Gaussian σ: Typically 2.0-3.0 for each pyramid level
  • Blend Width: Automatically determined by distance transform, ensuring smooth transitions

  • Local adaptation: Blending adapts to local image content rather than using global linear weights

Part B: Feature Matching for Autostitching

Automatic Feature Detection and Matching

In Part A, we manually selected correspondence points to compute homographies. Part B automates this process by detecting distinctive corner features, describing them with invariant descriptors, matching them across images, and using RANSAC to robustly estimate homographies. This enables fully automatic panorama stitching.

Pipeline Overview

  1. Harris Corner Detection: Identify distinctive corner points in each image
  2. Adaptive Non-Maximal Suppression (ANMS): Select a spatially distributed subset of the strongest corners
  3. Feature Descriptor Extraction: Describe each corner with a normalized 8×8 patch descriptor
  4. Feature Matching: Find corresponding features between image pairs using nearest neighbor ratios
  5. RANSAC: Robustly estimate homographies by filtering outlier matches

B.1: Harris Corner Detection

Detecting Interest Points

The Harris corner detector identifies points in an image where intensity changes significantly in multiple directions. These corner points are stable, distinctive features that can be reliably detected across different views of the same scene.

1. Harris Corner Response

Mathematical Foundation

For each pixel, we compute the structure tensor (second moment matrix) from image gradients:

M = ⎡ Σ Ix² Σ IxIy ⎤
⎣ Σ IxIy Σ Iy² ⎦

The Harris corner response is computed as:

R = det(M) - k × trace(M)²

Where k ≈ 0.04-0.06. Points with large positive R values are corners.

3. Adaptive Non-Maximal Suppression (ANMS)

Why ANMS?

Raw Harris detection produces thousands of corners clustered in high-texture regions. ANMS ensures a spatially distributed set of features by suppressing corners that have stronger corners nearby.

Algorithm

For each corner i with strength fᵢ, compute its suppression radius rᵢ:

rᵢ = min ||xᵢ - xⱼ|| where fⱼ > c_robust × fᵢ

We then select the N corners with largest suppression radii, ensuring spatial distribution.

ANMS Benefits

  • Spatial Distribution: Features spread across entire image, not clustered
  • Improved Matching: Better coverage of the scene leads to more reliable homography estimation
  • Efficiency: Reduces number of features from thousands to hundreds

B.2: Feature Descriptor Extraction

Describing Features

Each detected corner is described by an 8×8 normalized patch extracted from a larger 40×40 window. This descriptor captures the local appearance around the corner in a way that's robust to illumination changes.

1. Descriptor Extraction Process

Multi-Scale Sampling

  1. Extract 40×40 window: Large window around each corner point
  2. Apply Gaussian blur: Smooth the window to reduce noise and aliasing
  3. Subsample to 8×8: Downsample to create a compact descriptor
  4. Normalize: Subtract mean and divide by standard deviation for illumination invariance

Normalization Formula

d_normalized = (d - μ) / σ

Where μ is the mean and σ is the standard deviation of the descriptor values.

B.3: Feature Matching

Finding Correspondences

To find matching features between two images, we compare descriptors using the Sum of Squared Differences (SSD). Lowe's ratio test filters out ambiguous matches by requiring that the best match be significantly better than the second-best match.

1. Matching Algorithm

Lowe's Ratio Test

For each feature in image 1:

  1. Find nearest neighbor: Feature in image 2 with smallest SSD
  2. Find second nearest neighbor: Feature with second smallest SSD
  3. Compute ratio: ratio = SSD₁ / SSD₂
  4. Accept match if: ratio < threshold (typically 0.6-0.8)

This test rejects matches where the best match is not distinctly better than alternatives, reducing false positives.

Matching Statistics

  • Initial features: ~500 per image (after ANMS)
  • Putative matches: ~100-200 pairs (after ratio test)
  • Outlier rate: 10-30% incorrect matches typical
  • Solution: Use RANSAC to filter outliers

B.4: RANSAC for Robust Homography Estimation

Filtering Outliers

RANSAC (RANdom SAmple Consensus) is a robust estimation algorithm that can compute accurate homographies even when 10-30% of matches are incorrect. It works by repeatedly sampling minimal subsets, computing candidate homographies, and selecting the one with most inlier support.

1. RANSAC Algorithm

4-Point RANSAC for Homography

  1. Repeat N iterations: (typically 1000-5000)
    • Randomly select 4 point correspondences
    • Compute homography H from these 4 points
    • Count inliers: matches with reprojection error < threshold (e.g., 3 pixels)
    • If this is the best model so far, save it
  2. Refit with all inliers: Use all inlier correspondences from best model to compute final H

Inlier Test

A match (x₁, x₂) is an inlier if:

||x₂ - H × x₁|| < ε

Where ε is typically 3-5 pixels.
